YUSRA — Design & Architecture Directive (v2.0)
1. Core Philosophy: The Autonomous Entity
Yusra is NOT a chatbot. She is an autonomous, local-first desktop entity built to surpass tools like Hermes and Claude Code. She operates on an agentic loop: she reasons, writes code, executes it locally, observes the results, and iterates. She requires zero cloud access.

2. UI/UX: The "Deep Carbon" Developer Aesthetic
The UI must feel like a multi-million dollar developer tool (think Linear, Arc Browser, Raycast).

Colors: Deep Carbon (#0A0A0C), Glass Panels (rgba(20, 20, 24, 0.7) with blur(40px)), Ice Cyan (#00F0FF).
Typography: Space Grotesk (Headers), JetBrains Mono (Code/Terminal), Inter (Body).
Layout (The Workspace):
No standard window chrome. Borderless, custom titlebar.
Left Pane (The Mind): A reasoning stream. Shows her thoughts, plans, and chat.
Right Pane (The Hands): A live, executing terminal/code block. When she writes a script, it renders here and runs.
Command Palette (Omni-Bar): Triggered by Ctrl+Space. Drops down from the top. Used for instant commands ("build a react component", "analyze this folder").
3. The Agentic Backend (Tauri + Rust)
Inference: Uses candle to load local GGUF models. If no model is present, prompts the user to download one via the LLM Fit checker.
Execution Engine: Uses std::process::Command to execute Python/Shell scripts generated by the LLM.
Safety Loop: High-risk commands (rm -rf, mkfs) are intercepted. A premium modal drops down asking for explicit user confirmation before execution.
Memory: A hybrid SQLite graph database. She remembers past commands, file paths, and user preferences.
4. Strict Implementation Rules
Use shadcn/ui and TailwindCSS for all components to guarantee a premium, consistent visual standard.
Use Framer Motion for all animations (smooth, physics-based spring curves).
NO MOCK DATA. If the LLM isn't loaded, the UI must reflect an "Offline" state. The UI must be fully wired to the Rust backend via Tauri IPC.
